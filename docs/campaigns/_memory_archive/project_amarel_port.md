**BUILD-REPRODUCIBILITY — wavemaker line FIXED (2026-06-16).** Root cause of the Amarel-rebuilt model's `uvmax>1000` instability = `build_wavemaker_line.py`'s `argmax(y)` trim. The −5 m CUDEM contour's SEGMENT CONNECTIVITY around the Sandy Hook spit is version-sensitive (contourpy 1.3.3 on Amarel stitches the open coast + Hook wrap into ONE segment; the desktop's contourpy split them). `argmax(y)` then kept everything up to the global northernmost point → on Amarel the line wrapped NW around the Hook to y≈4481748 (37.83 km / 11 verts) vs desktop's open-coast-only y≈4478201 (33.69 km / 8 verts). The 3 extra Hook-wrap vertices put wavemaker points on the L3 refinement boundary → SFINCS unstable. Both lines are IDENTICAL through the open coast (verts 0–7); only the northern tail differed. FIX: replaced `argmax(y)` with a fixed northing cap `Y_OPEN_COAST_MAX=4_478_500` (keep S→N coords below it). Re-run on Amarel → 33.96 km / 8 verts, y_max 4478472 = matches desktop, Hook wrap gone. The committed `data/wavemakers/wavemaker_line.geojson` now holds this reproducible line. NOT YET re-confirmed by a full from-scratch Amarel rebuild+solve (the definitive test — expensive, overwrites the known-good desktop-built `model_quadtree`); user to decide when/where to run it.
